# Проверка дизайн-пакета

Область проверки — статическая спецификация и отрендеренные макеты. Работа оригинального GUI, Flutter-приложения и безопасность расчётных моделей здесь не проверяются.

## Методы

Структурный аудит сопоставляет 455 записей исходного UI-реестра с целевыми экранами/исключениями; проверяет динамические якоря контроллеров, связи requirement→screen→board→scenario, ссылки и происхождение численных примеров. Для каждой комбинации размеров/темы/масштаба проверяется сохранение всех полей из screen-model, последовательность срезов, наличие графиков, размеры SVG/PNG и геометрические ограничения. SHA-256205 файлов исходного дистрибутива сверяются с исследовательским манифестом.

Контраст проверяется формулой относительной яркости sRGB для 34 разрешённых непрозрачных пар. Минимумы:4.5:1 для обычного текста,3:1 для значимых границ/фокуса. Случайные цвета и прозрачные наложения макетами не используются.

Визуальная проверка: полноразмерные примеры каждой группы экранов, обеих тем, маленького телефона, desktop и граничных компоновок; контактные листы показывают все срезы. Проверяется отсутствие обрезки, наложения текста, нечитаемых длинных названий и потери полей. SVG `<desc>` и manifest содержат ID, тему, размер, состояние и источник данных; подробные аннотации взаимодействий находятся в screens/flows.

## Исправления при проверке

- Заголовок при 200% пересекался с подписью макета: компактный app bar с заголовком 20→40, маркировкой МАКЕТ и кнопкой Меню освобождает место для формы. Длинный footer заменён на «Срез N/M»; для карточек добавлена проверка границы перед footer.
- Длинная подпись мобильной навигации выходила за границы: визуальная подпись Инстр.; semantic полное имя Инструменты указано в handoff.
- Заголовки с переносом требовали дополнительного места: header растёт, карточки сдвигаются вниз.
- Подпись состояния могла накладываться на конец длинной карточки: зарезервирован отдельный зазор 32 перед footer.
- Первые схемы полей выглядели как обычный текст: добавлены подписанные поля с постоянными единицами и областью не меньше 48.
- У графиков явно разделены шкала глубины вниз и шкала давления вверх; серии имеют линию/штрих и текстовую легенду.
- Технические revision и имена состояний убраны из основного визуального статуса; они остаются в handoff/метаданных для разработчика.

## Численные данные

P04 и V-print: fixture `oc-air-30m-20min`, режимOC, BühlmannB, воздух 30м/20мин; отдельные проверенные величины runtime28, ascent7.333, deco5.333, CNS5.084%, OTU13.388, остановки и раскрытая строка 12м. Это новые форматы отображения исходных чисел, не обещание идентичного округления старого UI. CCR-поля показаны отдельной карточкой без выдуманных чисел.

T03: `custom-gas-original-controller`, только O2/He и входные условия. T05: `topoff-original-controller`, итоговый состав. T06: `equalizer-original-controller`, итоговое давление. T08: `cost-original-controller`, объёмы 1200/1680л, цены и итог 1306.00. Остаточный N2 и части суммы — явно производные отображения. Остальные заполнения, кривые и сценарии ошибок иллюстративные. Результаты не выполнялись повторно: сверка идёт с сохранёнными JSON оригинального runtime.

## Ограничения и передача

Fira Sans/обычная Fira Code не доступны в текущем fontconfig; SVG отрендерены Verdana. Метрики окончательного шрифта, системные поля, фактический keyboard focus, hit testing, largest Dynamic Type, VoiceOver/TalkBack/Narrator, resize и reduced motion должны проверяться в будущем Flutter-приложении. МатрицаRT01–RT12 в flutter-handoff.md имеет статус **не выполнялось** на всех четырёх платформах.

Часть макетов показывает альтернативные режимы и описательные группы действий рядом для проверки состава полей. Это аннотированные wireframes, не пиксельный снимок работающего UI. Макеты 200% — проверка рефлоу и срезов формы, не эмуляция системного accessibility stack. Поведение gesture/animation нельзя подтвердить PNG.

Восстановление ядра остаётся частичным по limitations.md. Наличие экрана VPM/высоты/SI не означает доступный успешный расчёт этих ветвей. Справочники, лицензия/обновление оригинала и отсутствующие резервы не смешиваются. Новое приложение/его платформенные сборки не создавались. Итоги структурного аудита и визуального просмотра приведены ниже.


## Итог

- 18 основных экранов,13 вариантов состояния;363 SVG и 363 PNG с продолжениями и размерной матрицей.
- 455 legacy-элементов:437 включены/перепроектированы,18 исключены с причинами. Дополнительно 28 динамических сценариев контроллеров.
- 15 требований связаны с экранами и сценариями; в 144 комбинациях screen/width/height/theme/scale ни одно поле screen-model не потеряно.
- 34 цветовые пары проходят заданные пороги; минимальное измеренное отношение 4.548:1.
- Хеши 205 защищённых входных файлов совпадают. Исходный дистрибутив и расчётный пакет не изменены.
- Все 16 контактных листов просмотрены; ключевые формы, таблица, графики, обе темы и проблемные 200%-срезы дополнительно просмотрены в полном размере. После исправлений наложений и обрезки на проверенных макетах не обнаружено.

Машинные результаты: [аудит](reports/artifact-audit.json), [контраст](reports/contrast.json), [покрытие требований](reports/requirement-coverage.json), [состав контактных листов](reports/contact-sheets.json). Индивидуальные SVG/PNG и параметры каждого среза перечислены в [манифесте](mockups/manifest.json). Геометрический аудит не является доказательством runtime-доступности, а маленькие контактные превью не заменяют полноразмерные примеры.

Изменения ограничены docs/ui и отметками задач выбранного OpenSpec change. Git-репозиторий отсутствует, поэтому git diff недоступен; область изменений проверена по созданным файлам и сохранности защищённого дистрибутива. Нет открытых замечаний, блокирующих передачу статического UX-пакета. Исполняемая реализация, платформенные тесты и завершение ядра остаются отдельными работами.
