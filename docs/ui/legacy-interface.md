# Разбор интерфейса оригинала

Исследуемая сборка: DecoPlanner 4.6.3, `business/dp.jar`, SHA-256 `c5b8d01df71e28d22a0c9f000548d1a5dce7f1b9dacd63175a4dd07c64151f28`.

Это статический аудит FXML и декомпиляции. Окно оригинала не открывалось. Наличие поля в XML не означает доступность действия: события и видимость проверяются в контроллере. Численные проверки из `analysis/fixtures` подтверждают только конкретные вызовы, а не работу всего GUI.

| Ресурс | Контроллер | Структура → новое представление |
|---|---|---|
| DP.fxml | DP | Панель кнопок, вкладки погружений, accordion настроек → P01, S01/S02 |
| OC.fxml | W | Уровни, декогазы, расход слева; таблица/профиль справа → P02–P06 |
| CC.fxml | R | Дилюент/setpoint, результаты CCR, переход bailout → P02–P07 |
| Bailout.fxml | Y | Смешанные CCR/OC уровни, газы и результат → P07 с общими компонентами P03–P06 |
| GasMixingTabPane.fxml | K | Семь инструментов → T01–T07 |
| GasMixingCostDialog.fxml | X | Диалог стоимости для результата смешивания → T08 |

| SplashScreen.fxml | SplashScreenLoader | Legacy-заставка и текст согласия → исключены |

Полный реестр: [feature-map.json](feature-map.json). Для каждой из 455 исходных записей сохранены исходный индекс, тип, ID, текст, onAction, ресурс, строка ресурса, ссылки на поле контроллера, целевой экран/компонент либо причина исключения. Совпадения строк контроллера — навигационные ссылки, не доказательство выполнения обработчика. Динамические сценарии имеют отдельные записи с точным якорем в исходнике.

## Динамические элементы

DP.initialize назначает W/R через FXMLLoader.setController и создаёт вкладку Next dive. R.bailoutPlanButton_InputAction вызывает addBailoutTab с исходными сегментами. W/R/Y.tablesButton_InputAction создают диапазонные таблицы; печать инициируется из сгенерированного диалога. W/R/Y.tissuePressureGraphButton_InputAction строят отдельное окно, выбор All/Comp.1–16 и линии тканей. Обработчики редактирования ячеек и выбора газа меняют состояние доступности результата. Контекстные действия и их точные подписи индексированы в dynamic-разделе JSON.

## Исключения и предлагаемые изменения

Регистрация, пользовательские лицензии, проверки обновлений, адреса поддержки и бренд GUE не являются функциями собственного планера. Ограничения Rec/Tech, зависящие от уровня лицензии, не переносятся как физиологическая валидация. Silver theme скрыта в FXML. W/Y явно скрывают reservesButton; расчёт резервов не обнаружен. Подпись «один дайвер, без резервов» сохраняется у расхода.

Новые решения UX, а не наблюдения оригинала: три глобальных раздела, revision входов, защита от устаревших ответов, сохранение формы при ошибке, явные типы bailout-сегментов, сводка ошибок, безопасные подтверждения, перенос выбранного газа явным действием. Эти улучшения не меняют формулы ядра.

Пробелы: интерактивная печать и полный GUI графиков оригинала не выполнены; результаты VPM-высоты/SI и редкие пределы смешивания имеют ограничения, описанные в [limitations.md](../calculations/limitations.md). Они не выдаются за успешные рабочие режимы будущего ядра. Полнота UX-реестра не означает полноту переноса вычислений.

Воспроизведение индекса: `python3 docs/ui/tools/build_reference.py`. Скрипт читает оригиналы и меняет только производный реестр в docs/ui.

## Локальные исследовательские проверки

Оригинал и анализ перемещены в игнорируемый `local/reference/`. Пути `analysis/...` в исторических данных относительны этой области. См. [инструкцию](../development/reference.md). `audit_design.py` по умолчанию проверяет только публичные материалы; `--with-reference` явно включает оригинальные источники, численные наблюдения и хеши. `build_reference.py` и `export_legacy_baseline.py` требуют локального архива.
