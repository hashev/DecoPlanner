# Расход газа и диапазоны расчётов

`calculateGasUsage(result, settings)` использует физические сегменты результата,
а не округлённые строки таблицы. Давление берётся из `result.pressure`, включая
фактическую высоту. Суммы не округляются до форматирования интерфейсом.

Для OC объём в стандартных литрах равен RMV × время × среднее абсолютное
давление / 1.01325 bar. Для линейного движения среднее давление даёт точный
интеграл. Для CCR учитывается только метаболический кислород: OCR × время,
без множителя давления. Дилюент, промывки, утечки и объём контура не рассчитаны.
Чистый кислород OC и кислород CCR имеют разные роли в итогах.

Пользовательские `levelTravel/levelHold` используют bottom RMV/OCR;
`ascent/decompression` — deco RMV/OCR. Каждый сегмент учитывается один раз.
Подъём между введёнными уровнями может содержать декомпрессию; он сохраняет
фазы, назначенные расчётным ядром. Дополнение следующей выдержки до целой
минуты входит в её фактическую длительность. Поэтому bottomMin нельзя
заменять суммой введённых пользователем времён.

`bottomMin` — фактическое время levelTravel/levelHold, `ascentMin` — всё время
ascent/decompression, `decompressionMin` — только остановки decompression.
Их определения сохраняются и для bailout, включая его префикс CCR. Общий
runtime равен bottomMin + ascentMin. Время на конкретном газе включает все
его фазы; среднее время остановки равно только stop-time / числу фактических
различных глубин остановок этого газа.

Группы остановок строятся на физической сетке: две самые мелкие позиции,
затем группы по пять (настраиваемо). В отчёте сначала глубокие группы.
Пустые позиции не увеличивают знаменатель среднего времени. Точные ratios
сохраняются; при нулевом bottomMin отношение недоступно. Округлённый вариант
для счёта в уме имеет явный флаг занижения и не заменяет точное значение.

`TankRequirement` возвращает линейную оценку bar = стандартные литры /
(водяной объём в литрах × число баллонов), без предварительного округления.
Отдельный флаг показывает превышение рабочего давления. Это оценка расхода
одного дайвера **без резервов**, без EOS-поправок, начального давления и
расчёта минимального газа. Имперские значения переводятся в канонические
единицы до вызова; отображение выполняет обратное преобразование.

## Независимые проверки

`gas-usage-quadrature.json` содержит 37 профилей из независимых полных
B/C OC, CCR и bailout расписаний, включая имперскую физическую сетку.
Генератор `tool/capture_usage_reference.py` использует mpmath с 70 значащими
цифрами для интегрирования OC и отдельной агрегации CCR/остановок; он не читает
Dart output. Хеши исходных fixtures и генератора находятся в provenance.
Допуск объёма 1e-8 L назначен в fixture до тестирования реализации.
Дополнительно тестируются реальные результаты B/C/VPM, нулевые расходы,
разделение ролей кислорода, суммы и ошибочные ёмкости.

## Диапазоны

`calculateRange` — ленивый поток ячеек по включительной сетке глубина × время
× вариант. Меняется только последний введённый уровень; предыдущие уровни,
состояние тканей, высота, SI и настройки сохраняются. `base` сохраняет все
switches, `noAdditionalGases` убирает OC switches, сохраняя CCR setpoint
switches, `noSwitches` убирает все switches. В bailout его начальный OC-газ
остаётся обязательным; дополнительные branch switches есть только у base.

Каждая ячейка содержит полный запрос и полный результат либо типизированную
ошибку. Ошибка одной точки не уничтожает соседние результаты. Отмена и
исчерпание общего бюджета прерывают диапазон. Число ячеек ограничено (по
умолчанию 1000); бюджет общий, по умолчанию 100000 итераций / 10 секунд.
Вызывающий worker должен явно назначить подходящий ограниченный бюджет для
большого диапазона и отдавать прогресс после каждой ячейки. Итерацию нельзя
выполнять на UI isolate. Тесты сравнивают каждую ячейку с отдельным полным
расчётом B/C/VPM; это проверка оркестрации, не новый независимый численный
эталон декомпрессии.
