# Заправка: объявленная модель и исправления

Идеальный и реальный partial-pressure расчёт выполняет компонентный баланс в
mol/L водяного объёма. Добавки: чистый O2, чистый He, выбранный top-up gas.
Решение максимизирует количество сохранённой исходной смеси при неотрицательных
добавках; необходимое стравливание выводится из этого количества через ту же EOS.
Для nitrogen-free top-up азотный баланс решается отдельно. Неосуществимая смесь
даёт `impossibleMixture`, неверные входы — `invalidInput`.

Условия по требуемой добавке заменяют ошибочные проверки исходного He/N2.
Порядок O2-first/He-first меняет промежуточные давления/составы; целевые количества
и итог одинаковы. Отсутствие добавок и точное сохранение исходного количества
не создают фиктивного стравливания из-за обратного численного преобразования.
Численно отрицательные аналитические нули допускаются лишь в явной границе
64 binary epsilon с масштабом количества; произвольные legacy пороги0.05/0.1
не применяются. Компонентные остатки проверяются после построения рецепта.

## EOS

`GasEquationOfState` содержит явные temperatureKelvin и realGas. mol/L, bar,
K; R=0.083145L·bar/(mol·K). vdW смеси: a=(Σf√aᵢ)², b=Σfbᵢ;
O2/N2/He a=1.382/1.37/0.0346, b=0.03186/0.0387/0.0238.
Это версия `vdw-double-v1` исследованной модели, не экспериментальное подтверждение
её точности. Используется double вместо legacy float и текущего static unit index.

P=RTn/(1−bn)−an². Только газовая ветвь выше расчётной критической температуры;
иначе явная доменная ошибка. При положительном P ограниченная бискекция ищет n
между0 и(1−1e−12)/b, residual tolerance1e−10·max(1,P)bar, максимум256 оценок
поиска и общий iteration/time budget. Нет неограниченного Newton.

25 корней проверены независимым mpmath1.3.0 при70 десятичных знаках, параметры
и provenance записаны в independent/vdw-mpmath.json. Ожидания не читают Dart.
Проверены идеальный аналитический рецепт, normal/drain/impossible, обе очереди,
несколько top-up gases и отдельный компонентный баланс. Пересчёт bar/psi —
граница ввода/вывода, не статический выбор внутри EOS.

## Табличный Z — отдельный путь

`RecordedCompressibility20C` использует записанные численные таблицы20°C с
provenance в parameters/z-observed.json. Oxygen/He/N2 взяты из первого записанного
набора, air — из второго; отсутствующие legacy-массивы не вызываются.
Это самостоятельные эмпирические Z-функции, не подмена vdW рецепта.

Узлы P=k·6.894942725bar, k1..40, плюс явный P0/Z1. На первом интервале линейная
интерполяция от0 устраняет ошибку индекса при6.89. После последнего узла явная
линейная экстраполяция от него с записанным slope, без скрытого clamp и скачка
округлённого intercept. Все160 узлов, обе стороны6.89/первого шага и непрерывность
экстраполяции проверены. Нечисловое/отрицательное давление отклоняется.

## Top-off, equalizer, баллоны и стоимость

Top-off идеальный: давление не уменьшается; equal-pressure case — identity.
Equalizer сохраняет идеальное PV двух баллонов и одинаковое давление — identity.
Водяные объёмы всегдаL, давлениеbar; преобразование входных единиц отдельно.
Нулевые/отрицательные ёмкости отклоняются.

CylinderCapacity сохраняет отдельную эмпирическую конверсию номинала:
freeL=Pbar·waterL/(1+0.0002615Pbar), затем ft³. Все raw числа сохраняются;
12L/232bar отображаются92.7ft³/3365psi. Обратная конверсия не округляет давление
внутри формулы, поэтому raw round-trip точный в пределах floating arithmetic.

Стоимость использует только добавленные mol/L из рецепта × waterL, перевод
в свободные литры через **явные** reference temperature/pressure и цены O2/He
за reference litre. Дозаправка оплачивается фиксированной ценой один раз,
только если добавлено ненулевое количество top-up газа, как в исходном X.B(). Оставшийся/стравленный газ не считается купленным.
O2/He fill order не меняет стоимость, zero prices допустимы. Состав/количества
берутся из текущего рецепта; актуальность UI recipeRevision проверяется позже
в слое приложения. Проверены PV/компонентные балансы, номиналы, raw round-trip,
оба порядка, цены и недопустимые входы.

## Continuous blending

`continuousMix` выдаёт отдельный `ContinuousRecipe` с сохранённым остатком,
стравливанием, общими покупаемыми O2/He/air и упорядоченными шагами. Variant1
(`twoStreams`) использует O2/He→nitrox; альтернативный путь nitrox→heliair
покрывает второй порядок источников. Variant2 (`singleStream`) подаёт одну
смесь. Перед потоками допускаются pure O2/He prefill. Каждый шаг хранит mol/L,
доли исходных потоков, feed gas, текущий состав и давление по выбранной EOS.
Пустой поток не создаёт шага. Значения остаются raw, без UI-округления.

Лимиты — максимальные молярные доли **O2 и He в каждом непрерывном потоке**,
в диапазоне0..1; это не расход в L/min и не разрешение оборудования на такую
смесь. Скорости не рассчитываются без заданного производительности компрессора.
Исходные потоки: O2, He, воздух21/79; для pure prefill указанные blend caps
не применяются. Nitrogen-free остаток/цель и zero limits обрабатываются явно.

Выбранная однозначная политика: сначала максимизировать сохранённое исходное
количество, затем сумму непрерывной подачи, затем первый поток, затем O2
добавленный в первый поток. Остаток и потоки решаются **совместно**, поскольку
лимит может потребовать дополнительного стравливания. Например, исходные120bar
He, цель21/35 при200bar: без caps сохраняются70bar He; при O2cap.19/He cap.9 —
58.27448367755bar, O2 prefill18.60759493671bar-equivalent, затем поток19/9.52381.
Рецепт с пределами нельзя получать простым ограничением результата обычного PP.

Компонентные балансы линейны в молярных количествах, включая зависимость
air=(targetN−retained·initialN)/.79. Реальная EOS определяет исходное/целевое
количество и промежуточные давления; состав feed остаётся молярным. В Dart
ограниченный перебор вершин3/4-переменной задачи с Gaussian pivoting, общий
CalculationBudget/cancel/time. Нет iterative repair или float порогов0.01/0.03bar.
Feasibility/lexicographic tolerance1e−12 нормированной target amount; итоговый
balance/amount/fraction residual2e−11, pivot singular threshold1e−13. Вне этих
границ — typed nonConvergence, пустая допустимая область — impossibleMixture.

Отличия от исходных constrained branches: оба caps соблюдаются в каждом feed;
исходный retained-остаток корректируется одновременно с ограничениями, пустые
потоки не делятся на0, отключены неограниченные repair loops и округление малых
ненулевых добавок до0. Обычный unlimited вариант1 сохранён как отдельный
`legacy_baseline/continuous-control.json` (float tolerance3e−5bar-equivalent,
1e−7fraction); эти допуски не распространяются на исправленные ветви.

486 независимых эталонов — `independent/continuous-highs.json`, SciPy1.18.1 /
HiGHS dual simplex с отдельными **явными** prefill/stream variables и тремя
balance equalities. Production исключает balances и перебирает вершины;
эталон использует другой solver и представление. Real amounts проверены
mpmath1.3.0 при70digits, NumPy2.5.4. Версии HiGHS, SHA его бинарника, linprog и
генератора записаны в provenance. Генератор не читает Dart или legacy ответы.
Тесты используют заранее зафиксированные2e−8 нормированного количества/долей,
1e−7bar final pressure,1e−8mol/L EOS; отдельные conservation assertions строже.
Два запуска с текущим генератором дали одинаковый SHA всего файла.

Воспроизведение (только исследовательское окружение):

```sh
local/oracles/python-env/bin/python -m pip install scipy==1.18.1 numpy==2.5.4 mpmath==1.3.0
local/oracles/python-env/bin/python tool/capture_continuous_reference.py
```

Математическая форма ограничений и solver API: [SciPy linprog HiGHS dual simplex](https://docs.scipy.org/doc/scipy/reference/optimize.linprog-highs-ds.html).
В продукт не добавлены SciPy, HiGHS, Python или исходный Java-код.
