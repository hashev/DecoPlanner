# Публикация DecoPlanner в Telegram

## GitHub Pages

1. После слияния workflow в `main` выберите **GitHub Actions** в **Settings → Pages → Source**. Для окружения `github-pages` разрешите деплой из ветки `main`.
2. Запустите **Publish Mini App** из `main`. Workflow проверяет, что выбранный SHA входит в историю `main` и имеет успешный **DecoPlanner CI gate**.
3. После деплоя проверьте опубликованный SHA в `revision.txt` и ответы HTTP для `flutter_bootstrap.js`, `main.dart.js` и `planner_worker.dart.js` под тем же базовым путём.
4. Для отката повторно запустите **Publish Mini App**, указав полный SHA предыдущего опубликованного релиза, совместимого со схемой IndexedDB.

## BotFather

В настройках бота выберите **Mini Apps → Main App**, укажите адрес [GitHub Pages](https://hashev.github.io/DecoPlanner/) с завершающим слешем и режим **Fullsize**. В клиентской сборке и в workflow токен бота не требуется.

- Публичный бот [@DecoPlannerBot](https://t.me/DecoPlannerBot?startapp)
- Тестовый бот [@DecoPlannerTestBot](https://t.me/DecoPlannerTestBot?startapp)

## Проверка клиента

Проверки в Telegram для Android и iOS проводят пользователи после публикации.

Откройте Mini App в Telegram и запишите версию клиента и ОС. Создайте план, рассчитайте его, сохраните, закройте Mini App и откройте снова. Отключите сеть с уже открытым приложением и повторите расчёт. Проверьте изменение поля с клавиатурой и системную кнопку «Назад» на телефоне.

Экспортируйте план, сохраните файл JSON из системного меню и импортируйте его. Проверьте несовместимый и повреждённый JSON. Откройте предварительный просмотр отчёта для актуального плана и диапазона. Отмените первый вызов меню сохранения, затем повторите действие и откройте полученный PDF. На macOS системное меню позволяет выбрать **Copy** и вставить файл в Finder.

Локальные данные привязаны к хранилищу WebView в клиенте Telegram. Для переноса между устройствами используйте экспорт JSON. При очищенном WebView или смене домена доступ к прежним данным может быть потерян.
