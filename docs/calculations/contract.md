# Контракт вычислительного ядра

Статус: восстановленный контракт исследуемой сборки. Формулы и порядок
выполнения описаны в тематических справочниках; ограничения покрытия и дефекты
перечислены в implementation-guide.md, auxiliary.md и отчёте coverage.json.
Это описание для новой реализации, а не готовый API существующего JAR.

## Вход

`PlanRequest`:

- `model`: `buhlmann-b`, `buhlmann-c`, `vpm-b`; `mode`: `oc`, `ccr`, `bailout`.
- `units`: metric или imperial. В оригинале давления представлены эквивалентной
  глубиной: `O.V` = 10.1325 м/ATA либо 33 ft/ATA. Не смешивать с множителем
  10.0 м/bar или 32.5684678 ft/bar для коэффициентов Bühlmann.
- `settings`: скорости спуска/подъёма, шаг глубины, минимум остановки,
  GF low/high, вариант B/C или VPM-консерватизм, последний стоп 6m/20ft,
  включение спуска в заданное время, RMV bottom/deco, CCR low setpoint,
  OCR bottom/deco, параметры высоты и акклиматизации.
- `gases`: идентификатор, O2/He как доли, N2 = 1 − O2 − He; роль bottom/deco,
  глубина разрешённого переключения, индивидуальный минимум остановки,
  CCR setpoint при необходимости. Исключённый/lost gas не попадает в активный
  список. Восстановленного расчёта резервов не обнаружено; баллоны используются для давления расхода.
- `levels`: глубина, длительность, газ, setpoint (0 означает OC в bailout).
  Длительность в режиме «include travel» включает спуск, но не любой подъём:
  правила подготовителя сегментов являются частью поведения.
- `initialState`: первый или повторный dive, ткани N2/He[16], CNS и OTU,
  поверхностный интервал, параметры состояния пузырьковой модели при наличии.
  Для VPM сохраняются также radii/crushing/allowable gradients и actual gradients
  по карте vpm.md; legacy reset перед SI — отдельное явное правило воспроизведения.

## Настройки по умолчанию оригинала

Источник: `O.C(boolean)` и отдельная ветвь чтения preferences в конструкторе
O.java (локально: `../../local/reference/analysis/decompiled/source/decoplanner/O.java`).

| Параметр | Reset defaults |
|---|---|
| Единицы, режим, модель | metric, OC, Bühlmann B |
| Скорости | спуск 10, подъём 9 м/мин |
| Шаг / минимум | 3 м / 1 мин |
| GF | 0.30 / 0.85 |
| Время спуска включено | да |
| Последняя остановка 6 м | нет |
| RMV bottom/deco | 20 / 15 л/мин |
| Low setpoint | 0.7 ATA |
| OCR bottom/deco | 0.7 / 0.5 л/мин |
| VPM | индекс 2, множитель 1.15 |
| Высота | выключена; reset хранит 1000 м, acclimatized=true, 0 м исходно, 3 ч подъёма, 2 ч ожидания |

Preferences имеют другие fallback-параметры высоты: 2000 м, acclimatized=false,
1 ч подъёма, 1 ч ожидания. Не полагаться на неявные prefs. Давление поверхности,
водяного пара и начальное N2 следует задавать явно: в конструкторе O есть отдельные
ветви, не всегда совпадающие с последующим переключением модели. Для повторяемых
примеров использовать явный набор настроек, записанный рядом с входами.
Неизвестных defaults в перечисленном наборе нет; допустимые границы UI и
границы функций VPM и legacy-дефекты описаны в vpm.md/altitude-repetitive.md.

## Внутренние сегменты оригинала

Исходный класс `decoplanner.d` (CFR `d_0`):

| Поля | Смысл |
|---|---|
| `R`, `C` | 0 constant, 1 ascent, 2 descent; C=true заданный пользователем |
| `V`, `S`, `B` | start/end depth, elapsed minutes |
| `U`, `I` | start/end runtime |
| `A` | индекс газа в J.H |
| `D`, `X`, `G` | O2, He, N2 в OC или эффективной смеси |
| `E`, `P`, `O` | diluent O2, diluent He, setpoint CCR |
| `W` | расход для сегмента |
| `T`, `K` | конечные ткани N2 / He[16] |
| `Q`, `H` | не используются поставленными классами |
| `L`, `J`, `M` | не используются поставленными классами |

Подготовитель разворачивает уровни в движение и постоянную глубину, записывает
времена и газ, затем ядро добавляет декомпрессию. Нельзя вызывать полное ядро на
пустой или неправильно подготовленной коллекции и считать его ошибки правилами UI.

## Выход

`PlanResult`: список всех сегментов с длительностями, runtime, глубинами,
газом/setpoint и снимками тканей; отдельные строки таблицы (с UI-округлениями);
конечные ткани N2/He, CNS/OTU; ascent time и внутреннее deco time, глубина начала
off-gassing; расчёты расхода/смешивания при соответствующем запросе.

В `J`: `Q/J` — начальные N2/He; `V/e` — конечные; `G/R` — начальные CNS/OTU;
`Y/A` — конечные; `n` — сегменты, `H` — газы; `I` — OC rows, `d` — CCR rows;
`D/c/f` — surface pressure, vapor pressure, исходное N2; `T/a` — runtime/depth;
`l/E` — суммарный ascent time / учитываемое ядром deco time; `Z` — off-gassing
start; `B/L` — максимальные отношения supersaturation и GF.

CNS в ядре — доля; отображаемый процент умножен на 100. Времена таблицы и
необработанные времена могут различаться. Новое ядро должно хранить необработанные
величины, а совместимость отображения проверять отдельно.

## Ошибки и состояние

Разделять: неверный JSON/контракт; недопустимый ввод UI; вычислительная ошибка
или отсутствие сходимости; зависание/таймаут; невозможность выполнить оригинал
из-за окружения. Исходник может только печатать сообщение и продолжать, либо
показывать Alert. Новая реализация должна возвращать явную ошибку; это отдельная
рекомендация, а не утверждение об исходном поведении.

Каждый независимый запрос начинается с чистых глобальных настроек и состояния.
Повторные погружения внутри одного запроса сохраняют фактическое состояние
оригинала; сериализованный снимок должен содержать все поля, которые действительно
влияют на следующий расчёт. Исследовательский адаптер не должен читать пользовательские
preferences или вызывать регистрацию/обновления.


## Результат восстановления и область переноса

Контрольные JSON содержат полный static snapshot выбранного VPM-ядра:
начальные/скорректированные/восстановленные радиусы N2/He[16], max crush,
исходные и текущие allowable gradients, Boyle gradients, max actual gradients,
phase-volume times и сохранённые ткани. Единицы каждого семейства определены
в vpm.md (radii m, gradients pressure-depth с явным Pa conversion). Runtime,
current gas и выбранные настройки сохраняются вместе с ними.

Контракт нового ядра должен хранить эти семейства смысловыми именами; raw
буквенные поля нужны только адаптеру legacy. Полное совпадение для падающих
VPM OC-высоты/SI не является успешным расчётом. В этих ветвях пакет даёт
диагноз и исходное исключение; исправленный результат требует нового эталона.
