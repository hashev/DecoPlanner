## Идеальные парциальные давления

Для текущих P0,O0,H0 и целевых P1,O1,H1 (доли, не проценты):

```text
N0=1-O0-H0; N1=1-O1-H1
needO = O1*P1-O0*P0
needHe = H1*P1-H0*P0
needN = N1*P1-N0*P0
addAir = needN/0.79
addOxygen = needO-0.21*addAir
addHelium = needHe
```

Для top-up другой смесью Otop/Htop/Ntop: `topUp=needN/Ntop`, затем
`oxygen=needO-Otop*topUp`, `helium=needHe-Htop*topUp`.
Если Ntop≈0, T.B(8 doubles) выбирает topUp по needO/Otop и ограничивает по He.

При отрицательной добавке исходник ищет необходимое стравливание: уменьшает P0
на наиболее отрицательную компонентную недостачу, делённую на её текущую долю,
повторяет баланс; также проверяет, хватает ли O2 после воздушного top-up.
В j.B(6 doubles) используется цикл с порогом изменения -0.05; достижение
отрицательного drain pressure возвращает flag=true и I=-1 («impossible»).
В T.B(8 doubles) пороги отличаются: -0.1 для изменения, проверки needN>.05 и
oxygen/helium need<-.01. Эти допуски влияют на малые отрицательные остатки;
не зажимать их произвольно при проверке совместимости.

Булев результат означает «нужно стравливание/необычная ситуация», не просто
успех/ошибка. Получить drain через j.D()/T.E(); -1 означает невозможность.
Добавки: j.B() oxygen, j.C() He, j.E() air; T.B()/C()/D() — oxygen/He/topUp.
Поля raw instance в JSON сохраняют неокруглённый баланс.

## Реальный газ: Q (van der Waals)

j.A(6 doubles) и T.A(8 doubles) преобразуют давления в количество вещества
через Q.A(P,O2,He), делают компонентный баланс в этом пространстве, затем
пересчитывают последовательные давления через Q.B(amount,O2,He).
O2-first/He-first влияют на промежуточные давления. ctor(boolean) задаёт порядок.

Для fractions `[O2,N2,He]`:

```text
aMix = sum_i sum_j sqrt(a[i]*a[j])*f[i]*f[j]
bMix = sum_i b[i]*f[i]
a = [1.382,1.37,0.0346]  (исходные float)
b = [0.03186,0.0387,0.0238] (исходные float)
```

Аккумуляторы aMix/bMix в оригинале float; изменение на double меняет последние
разряды. Таблицы физических единиц Q: L=[.023658,.083145], pressureReference=
[14.7,1.013], temperature=[530,294]; индекс 0 imperial, 1 metric.
Конверсия a между системами использует .01808, b — .03531.

Пусть RT=temperature*L, P — давление, a/b после конверсии. Q решает кубическое
уравнение для V:

```text
P*V^3 - (P*b+RT)*V^2 + a*V - a*b = 0
Vinitial=RT/P
Newton: V -= polynomial(V)/derivative(V)
terminate when abs((Vold-V)/V) < pressureReference*RT/(20*P^2)
amount = RT/(pressureReference*V)
```

Количество D фиксировано 1 в реализации. Обратное преобразование:
`V=RT/(pressureReference*amount)`, `P=RT/(V-b)-a/V^2`.
При P=0 Q.A возвращает 0. Newton не имеет явного предела итераций: необходим
внешний таймаут и отдельная рекомендация о пределе для новой реализации.
Q.B зависит от ранее установленного unit index и temperature: отдельно вызванная
в новой JVM обратная функция не является независимой чистой функцией.

## Табличные поправки Z

Альтернативные поправки используют таблицы с шагом **6.894942725 bar**,
массивы по 40 значений, temperature field A=20. Снимки двух вариантов конструктора
сохранены в `analysis/coefficients/mixing.json`. Для P<6.89 возвращается 1;
до 275.79 линейная интерполяция между соседними значениями, индекс floor(P/step)-1
с верхним ограничением 38. На узкой границе [6.89,6.894942725) возможен индекс -1:
это следует проверять отдельно, а не молча менять границу. Выше диапазона —
линейная экстраполяция с константами, сохранёнными в байткоде.

Z.B(D) — O2, Z.D(D) — He, Z.A(D) — air, Z.C(D) — N2. Варианты конструктора
заполняют разные массивы; не считать каждый метод доступным для любого варианта.
Для смеси `Zmix=sum(f_i*Z_i(partialPressure_i))`, затем корректируемые парциальные
давления умножаются на Zmix/Z_i. Этот путь отличен от EOS Q: нельзя объединять
их в одну «поправку реального газа». Текущий UI partial-pressure выбирает Q через
j/T; Z встречается в дополнительных ветвях, состояние которых надо инициализировать.

## Непрерывное смешивание i

i.A(float×8,int,boolean) использует float: исходный/целевой состав и давление,
пределы O2/He, вариант смешивания 1/2, флаг режима. После общего баланса:

- Вариант с предварительной смесью He/O2: выделить air=needN/.79, pureO=needO-.21*air.
  Если хватает O2-limit для He/O2 смеси, объединить pureO+He в один поток,
  затем air. Иначе разделить поток при O2-limit и остаточный nitrox/air;
  при необходимости отдельно добавить O2.
- Вариант с добавлением в общий air stream: сначала air+He, затем довести O2,
  ограничивая итоговый O2-limit; оставшийся pureO вынести в отдельную добавку.
- При ограничении He отдельные ветви делят потоки на два этапа, подбирая расход
  по компонентному балансу до соблюдения обоих limits. Численные пороги .03/.05,
  округления F.A(...,3/5) и float-арифметика входят в алгоритм.

Выход: F pureO, I pureHe, J pressure первого потока, G/R его O2/He fractions,
H pressure второго потока, N/P его O2/He fractions; E — наличие второго потока,
L — drain pressure. M/C/A в этом классе объявлены, но не заполняются этим методом.
Для полной реализации вариантов использовать эту карту вместе с сохранённым
псевдоматематическим балансом и контрольными потоками; редкие сочетания limits
имеют меньшую степень runtime-покрытия, чем обычный partial-pressure.

## Стоимость и объёмы

X.B(): tank.G() даёт объём на единицу давления в текущих единицах.

```text
oxygenVolume = oxygenAddedPressure*tankCapacityPerPressure
heliumVolume = heliumAddedPressure*tankCapacityPerPressure
cost = oxygenVolume*oxygenUnitPrice + heliumVolume*heliumUnitPrice
       + (needsTopUp ? flatTopUpPrice : 0)
displayedCost = HALF_UP(cost,2)
```

Цена top-up **фиксированная**, не за литр. UI defaults: O2 .10, He .70, top-up10.
Цены задаются явно, валюта не встроена в математическую формулу. Пример 50bar O2,
70bar He, 24L, нужный top-up → 1200L O2,1680L He,1306.00 стоимости.
`cost-original-controller` проверяет именно исходный X с FXML и полями.

Статическое наблюдение по real-gas drain j.A/T.A: часть условий проверяет
отрицательность текущего He/N2 amount вместо отрицательности требуемой добавки.
При обычных неотрицательных входах эти ветви не срабатывают. Это потенциальный
дефект отдельных real-gas drain-случаев; отдельная runtime-матрица ещё не выполнена.
При переносе не считать успешный обычный real-gas пример доказательством всех
вариантов стравливания.
