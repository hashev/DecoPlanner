# Дефекты, ограничения и степень готовности

**Статус: пакет исследования завершён; готовность полностью совместимого нового
планера — частичная.** Есть воспроизводимые данные для основных расчётов, но
исправленные ветви и безопасность нового приложения требуют собственной проверки.

## Подтверждено выполнением оригинала

| Факт | Доказательство / последствие |
|---|---|
| VPM OC altitude обращается к null context | `altitude-vpm-acclimatized`, `altitude-vpm-travel`; H.F() вызывается до H.b=J |
| VPM OC surface interval выходит за массив | `repetitive-vpm-*`; H.B(D) использует1..16 при length16 |
| CCR VPM отличается | `altitude-vpm-ccr`, `repetitive-vpm-ccr` выполняются; нельзя распространять H-ошибку на D |
| Нулевая RMV даёт NumberFormatException | `oc-zero-rmv-controller`; пустая строка gas volume возвращается в Double.parseDouble |
| Нулевая выдержка/профиль может падать | `zero-hold-after-descent`, `zero-depth-zero-duration`; см. сохранённое корневое исключение |
| Z при P=6.89 обращается к индексу-1 | `z-interpolation-boundary-defect`; guard6.89 не совпадает с interpolation step6.894942725 |
| MOD с O2=0 возвращает Infinity | `mod-zero-oxygen-original`; UI отвергает ввод, private/public формула защиты не имеет |
| Неверные скобки root solver не дают явного отказа | `vpm-d-bad-bracket`, `vpm-h-bad-bracket`; печатается3565 и возвращается число вне скобок |
| SI=0 меняет ткани Bühlmann | `repetitive-b-0`, `repetitive-c-0`; цикл включает i=0 |
| CNS recovery использует целые часы | SI0/45/60/180/1440; M.A(II) содержит integer n/60 |
| High-PO2 CNS различается между ядрами | `oxygen-*-1.9`; S прибавляетduration, A/D/H фиксированное2.0 |
| Отсутствуют найденные резервы | W/Y скрывают кнопку; найден расход для одного дайвера без резервов, не reserve model |

Полный список реальных исключений — `analysis/reports/coverage.json`.
Случай с воспроизведённым исключением проверяет диагноз, но не создаёт эталон
успешного расчёта. Выходы с Infinity или диагностикой root solver тоже не
становятся корректными числами из-за отсутствия process exit error.

## Подтверждено байткодом, покрытие исполнения ограничено

- D.F() вычисляет altitude tissue adjustments до последующего копирования J.Q/J;
  эти временные массивы перезаписываются. Radius side effects могут сохраняться.
- VPM critical-volume convergence принимает ANY ткань с изменением≤1мин;
  у внешнего цикла нет явного максимума. Это исследовано на нормальных профилях,
  но не доказано завершение на всех входах.
- Основной VPM-метод отбрасывает возвращаемый projected-ascent candidate (`pop2`).
- CNS movement перебирает0..9 при таблице1..10; верхняя полоса пропускается.
- В j/T real-gas drain есть условия по исходному He/N2 amount вместо требуемой
  добавки; последствия для отдельных смесей ещё не проверены выполнением.
- Q Newton не имеет максимального числа итераций; реальный газ зависит от
  установленного ранее static unit index/temperature.
- График использует отдельные интерполяции и surface-константы; есть признаки
  расхождения отображения с моделью. Chart series не проверены выполнением.
- Ограниченные ветви continuous blending статически разобраны; runtime-матрица
  редких limits не исчерпывающая. Это отдельный пробел покрытия переноса.

Ни одно из этих условий не было исправлено внутри исходного JAR.

## Пределы артефактов декомпиляции

CFR выдал44 файла, в которые вложены327 классов. Имена и комментарии оригинала
не восстановлены автоматически. Реестр различает emitted-unverified и partial:
внешние JavaFX-типы на первом проходе не были доступны CFR; некорректный цикл
копирования в M — ошибка декомпиляции, не подтверждённая ошибка исходного M.
Байткод всех классов сохранён отдельно; case-insensitive коллизии A/a устранены
суффиксами. module-info читается из точного JAR URL, чтобы javap не выбирал
одноимённый дескриптор JDK.

Нет немодифицированного официального JAR. Выводы относятся к архиву с хешем
из manifest.json, а утверждение GUIDE «прочие классы не менялись» не доказано.
Формулы/коэффициенты из этой сборки нельзя объявить универсальным официальным
стандартом GUE. Для платформы будущего планера нужны отдельно выбранные требования.

## Что ещё потребуется для промышленного планера

1. Зафиксировать, какие legacy-дефекты исправляются и какое поведение считается
   целевым, сохранив исходные отрицательные эталоны.
2. Получить независимые успешные эталоны для исправленных VPM OC altitude/SI
   и других изменённых ветвей; одно исправление индекса не подтверждает математику.
3. Дополнить coverage всех выбранных функций, особенно continuous limits,
   ошибочные параметры, модель состояния и единицы.
4. Спроектировать резервы отдельно, если они нужны.
5. Проверить новое численное ядро и его область применимости независимо от
   воспроизведения DecoPlanner; UI и публикация входят в отдельную работу.

Известные пробелы не скрыты отметками OpenSpec: завершены задачи исследования,
а не реализация и валидация нового планера.
