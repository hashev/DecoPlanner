# Spec Delta

## Purpose

Предоставить проверяемое, независимое от языка программирования описание расчётного поведения исследуемого планера для последующей реализации собственного ядра.

## ADDED Requirements

### Requirement: Инвентаризация расчётного поведения
Справочник MUST перечислять все обнаруженные категории расчётов, их входы, выходы, зависимости, режимы применения и статус восстановления. Отсутствие функции MUST отличаться от отсутствия доказательств её реализации.

#### Scenario: Обзор покрытия
- **WHEN** разработчик открывает индекс расчётов
- **THEN** он видит покрытие декомпрессии, газов, кислородной нагрузки, высоты, повторных погружений и других обнаруженных численных результатов с указанием пробелов

### Requirement: Описание математической модели
Для каждого восстановленного расчёта справочник MUST указывать формулы или псевдокод, коэффициенты, единицы, диапазоны входов, состояние, начальные условия, порядок операций, округления, критерии завершения и ошибки со ссылками на доказательства.

#### Scenario: Независимое воспроизведение формулы
- **WHEN** разработчик реализует описанный расчёт без чтения Java-кода
- **THEN** документация определяет необходимые входы, преобразования и ожидаемые выходы без неявных значений по умолчанию

### Requirement: Полный цикл декомпрессионного расчёта
Справочник MUST описывать обнаруженные варианты Bühlmann B/C с GF и VPM-B для OC/CCR/bailout, включая загрузку тканей, потолок, построение остановок, смены газов/setpoint и перенос состояния между погружениями.

#### Scenario: Построение профиля
- **WHEN** читатель прослеживает путь от входных сегментов до таблицы остановок
- **THEN** описаны выбор модели, инициализация, переходы состояния, шаги поиска, граничные условия и формирование результата

### Requirement: Разделение доказательств и предположений
Каждый вывод MUST иметь статус «подтверждено байткодом», «подтверждено выполнением», «гипотеза» или «не восстановлено»; допускаются несколько подтверждений. Публичное описание модели MUST NOT заменять доказательство поведения этой сборки.

#### Scenario: Неясное условие ветвления
- **WHEN** назначение условия не удалось подтвердить
- **THEN** справочник сохраняет исходное условие, гипотезу, последствия неопределённости и способ её проверки

### Requirement: Контракт будущего ядра
Материалы MUST определять независимые от UI входы, выходы, ошибки и сериализуемое состояние будущего ядра, отделяя наблюдаемое поведение оригинала от рекомендуемых изменений.

#### Scenario: Подготовка реализации
- **WHEN** разработчик выбирает язык будущего планера
- **THEN** контракт позволяет перенести вычисления без зависимости от интерфейса и глобальных настроек исходного приложения
