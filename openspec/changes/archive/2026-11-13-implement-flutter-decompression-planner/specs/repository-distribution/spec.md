# Spec Delta

## Purpose

Обеспечить понятный и воспроизводимый состав репозитория собственного приложения, исключив локальный дистрибутив оригинала и служебные данные без потери результатов исследования.

## ADDED Requirements

### Requirement: Публикуемый состав
Репозиторий MUST включать исходники приложения/ядра, платформенные проекты, необходимые ресурсы, проверяемые тестовые данные, документацию и фиксированные зависимости. Исходный JAR/runtime, декомпиляция, локальные зависимости анализа, пользовательские планы, секреты и результаты сборок MUST быть исключены из подготовленного к публикации состава.

#### Scenario: Проверка списка файлов
- **WHEN** формируется состав будущего Git-коммита
- **THEN** в нём отсутствуют оригинальный дистрибутив, локальное исследование, ключи подписи и кэши, а необходимые ресурсы сборки не скрыты излишне широкими правилами

### Requirement: Сохранность локального архива
Упорядочивание каталогов MUST сохранять содержимое оригинального дистрибутива, исследовательские данные и происхождение эталонов. Перемещение MUST сопровождаться проверкой хешей и обновлением активных путей/инструкций; существующие архивированные спецификации не переписываются ради новых путей.

#### Scenario: Перенос в локальный архив
- **WHEN** исходные файлы и анализ перемещены из корня в локальную область
- **THEN** хеши исходных файлов совпадают, локальная инструкция позволяет воспроизвести анализ, а новый проект не зависит от наличия этой области

### Requirement: Проверка чистого checkout
Из публикуемого набора MUST быть возможно восстановить зависимости, выполнить анализ и автоматические тесты и собрать приложение доступной целевой платформы без скрытых локальных файлов. Документация MUST указывать проверенные SDK, команды, платформенные ограничения и происхождение сторонних ресурсов/данных.

#### Scenario: Изолированная проверка
- **WHEN** публикуемый набор развёрнут во временной чистой директории без local/reference
- **THEN** зависимости, тесты и доступная платформенная сборка проходят по описанным командам, а частные исследовательские проверки явно отделены от обязательных

### Requirement: Границы подготовки GitHub
Подготовка MUST оставить понятный локальный Git-репозиторий и проверенный состав файлов без автоматического создания remote, commit, push, CI/CD и публикации сборок. Лицензии третьих сторон MUST быть сохранены; собственная открытая лицензия MUST NOT выбираться без решения владельца.

#### Scenario: Завершение подготовки
- **WHEN** приложение и репозиторий подготовлены
- **THEN** доступен отчёт о составе и проверках, а удалённый репозиторий, workflows и опубликованные релизы не создаются
