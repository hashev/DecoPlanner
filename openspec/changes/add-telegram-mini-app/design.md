# Design

## Context

Интерфейс и `deco_core` уже разделены. Фоновые сервисы расчётов, PDF и кодирования документов используют Dart isolates. Репозиторий документов и файловые действия зависят от `dart:io`. CI собирает нативные цели на Flutter 3.41.6.

## Goals / Non-Goals

Цель — использовать единое ядро расчётов, формат документа и сценарии Flutter на нативных платформах и в Mini App. Первую версию ограничиваем локальными документами, ручным переносом через JSON и запуском через BotFather. Холодный запуск Mini App без сети остаётся вне требований.

## Decisions

### Платформенные границы

Добавить Flutter Web и выбирать реализации на границах расчётных исполнителей, хранилища и файловых действий. Начать со стандартной веб-сборки JavaScript. Расчёт плана и диапазонов выполняет Web Worker из того же Dart-ядра. Сообщения сохраняют идентификатор запроса, версии входов и модели. При отмене или таймауте исполнитель прекращает работу, а ответ от старого запроса игнорируется. Проверить отдельно сериализацию документов и генерацию PDF, поскольку их нативные исполнители также используют isolates.

### Документы и экспорт

Хранить библиотеку в IndexedDB с транзакционной записью и версией схемы. Переиспользовать кодек и проверки импортируемого документа, проверять актуальность восстановленного результата по версии модели и входам. Обрабатывать ошибки открытия базы и записи явно. JSON остаётся резервной копией при очистке данных WebView или смене устройства. Проверить выгрузку JSON и PDF в реальных клиентах Telegram до фиксации способа скачивания. Если кнопка скачивания не работает в целевом WebView, подобрать браузерный или системный способ сохранения файла и проверить его в том же клиенте.

### Запуск и доставка

Подключить небольшой адаптер Telegram WebApp для сигнала готовности, навигации назад и безопасных отступов. Для запуска достаточно настройки Main Mini App в BotFather. Токен бота хранится вне артефакта, сетевой обмен планами отсутствует. Собирать клиент, worker и его ресурсы с учётом базового пути Pages. Проверка веб-сборки входит в CI. Для первой версии публикация запускается вручную для проверенной ревизии через GitHub Actions и окружение GitHub Pages.

## Risks / Trade-offs

- Telegram WebView может ограничить хранение и скачивание. На первом этапе проверить перезапуск, отказ хранилища, JSON и PDF на iOS, Android и Desktop.
- Длительные вычисления и генерация отчётов чувствительны к устройству. Проверить тяжёлый диапазон, отмену и ввод во время работы.
- После публикации кэш WebView может удерживать старые ресурсы. Проверить обновление сборки и согласованность версий клиента и worker.

## Migration Plan

Сначала проверить тестовый Main Mini App, опубликованный по адресу с тем же типом базового пути. После прохождения проверок развернуть проверенную ревизию и указать постоянный HTTPS-адрес в BotFather. При регрессии повторно опубликовать предыдущую проверенную сборку с прежним URL. Изменения схемы IndexedDB должны учитывать совместимость с откатом. При первом выпуске перенос документов выполняется через JSON.
