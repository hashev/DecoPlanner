# Proposal

## Why

Публичному DecoPlanner нужны автоматическая проверка изменений и воспроизводимые релизы. Сейчас workflows отсутствуют, main не защищена, Android release использует debug-подпись.

## What Changes

- CI для PR в main и изменений main: форматирование, анализ, тесты приложения/ядра, публичные аудиты и платформенные сборки.
- Защита main, включая владельца: только PR с успешным CI, без обязательного approving review; запрет force push и удаления.
- GitHub Releases по стабильным тегам vMAJOR.MINOR.PATCH: Windows x64 ZIP, macOS ZIP, универсальный Android APK и SHA-256.
- Android устанавливается из скачанного APK, как ffido: отдельный постоянный ключ, GitHub Secrets, проверка сертификата и обновления поверх предыдущей версии. Ключей сейчас нет; их создание и резервное копирование входят в реализацию.
- Подготовка идентификаторов приложения к первой публичной сборке, документация выпуска и установки.
- Вне области: магазины, iOS, встроенное автообновление, покупка сертификатов Windows/Apple, notarization macOS. Desktop-сборки первоначально без доверенной подписи издателя; ограничения установки документируются и проверяются.

## Capabilities

### New Capabilities

- `continuous-integration`: обязательные автоматические проверки изменений и платформенных сборок.
- `tagged-release-delivery`: проверенные релизы трех платформ, подпись Android и совместимость обновлений.
- `protected-main`: PR и успешный CI как обязательный путь изменения main.

### Modified Capabilities

- `repository-distribution`: отделить завершенную подготовку репозитория от явно разрешенной последующей настройки CI/CD.

## Impact

Будут затронуты .github/workflows, служебные скрипты/их тесты, Android Gradle и идентификаторы платформ, документация, GitHub rulesets и Secrets. Flutter 3.41.6 / Dart 3.11.4 сохраняются. Расчетные алгоритмы и UI не меняются; приватный local/ не требуется. Существующая политика PR только от collaborators сохраняется.
